# 网络故障排查与修复

## 确定要恢复的路径

确认设备和当前网络、失败应用或目标地址与端口、错误与时间，以及用户期望走直连还是 VPS。优先从生效配置和日志提取这些信息；缺少会改变排查路线的信息时，再向用户确认。限定在用户有权管理的设备、VPS 和指定目标上测试。

| 要验证的路径 | 读取 |
| --- | --- |
| 应用 → 本机网络 → 目标。也用于单独检查本机到 VPS 入口的物理网络。 | [直连排查](references/direct.md) |
| 应用 → FlClash/Mihomo → VPS → 目标，或 SSH 登录 VPS。 | [VPS 排查](references/vps.md) |
| 比较直连和 VPS。 | 读取两份参考。固定设备、网络、目标、端口和测试时段，分别记录两条路径及其 IP 协议族。 |

## 从观测结果选择修复

1. **复现并记录实际路径。** 读取当前启用的配置、代理模式、TUN 状态、接口和路由。遇到间歇超时，在相同条件下复测，再换一条独立网络作对照。每次只改变一个条件。
2. **找到最先失败的一层。** 按需检查解析、选路、TCP 握手、SSH 或 TLS 握手、代理转发和应用响应。目标是 IP 时可以从路由和 TCP 开始。记录最深已验证的阶段；对同一个故障保留成功和失败的样本。
3. **修复已定位的层。** 配置引用缺失就修复生效配置，监听缺失就核对服务日志与配置，只有回程证据时就保留抓包并交给网络方核查。改动前保留可恢复的配置和管理入口。已经授权的可逆改动可直接执行；扩大公网监听范围、重启整机或重装时核对授权范围和影响。测试时临时切换的配置或选组，测完恢复，用户要求保留的选项除外。
4. **用原请求验收。** 在用户要保留的路径上重做失败操作，核对实际接口或代理链、响应和必要时的出口 IP。SSH 验收到用户需要的认证或登录阶段；代理涉及 UDP、登录、播放或重启恢复时，分别验证并报告状态。

交付最小证据链：目标与路径、失败阶段及对照结果、实际变更或恢复方式、原操作复测结果，以及尚未确认的故障范围。分享日志前去除凭据、控制器密钥和会话内容；需要报障时提供最小报文摘要。
