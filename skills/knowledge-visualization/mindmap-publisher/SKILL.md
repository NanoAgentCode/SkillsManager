# Mindmap Publisher

## Overview

Use this skill only after a mindmap has already been generated by `mindmap-builder` or an equivalent process. This skill copies the single-file HTML as `index.html` (or legacy HTML plus its referenced `markmap-assets/`) into a static publishing directory and returns the corresponding HTTP(S) URL.

Do not use this skill for local double-click HTML output. Use `mindmap-builder` for that.

## Required Inputs

Before publishing, require all of these values:

- `SourceHtml`: path to the generated mindmap HTML file.
- `StaticRoot`: server/static directory that maps to the public URL path.
- `PublicBaseUrl`: public origin, for example `https://example.com`.
- `PathPrefix`: required URL path prefix, for example `/mindmaps`. Do not default, infer, or leave empty.
- `Slug`: destination folder name under the path prefix, for example `zero-trust-ai-agents`.

Reuse explicit inputs and the configured hosting mapping. Ask for the missing values together before writing, including a user-supplied non-root `PathPrefix`.

## Publishing Model

Default source is a self-contained `output.html`; default published result is `{StaticRoot}/{Slug}/index.html`. No asset folder is needed. Legacy folder-based output is also supported:

Legacy source:

```text
source/
  output.html
  markmap-assets/
    d3.min.js
    markmap-view.js
    markmap-toolbar.js
    markmap-toolbar.css
```

Legacy published result:

```text
{StaticRoot}/{Slug}/
  index.html
  markmap-assets/
    d3.min.js
    markmap-view.js
    markmap-toolbar.js
    markmap-toolbar.css
```

Returned URL:

```text
{PublicBaseUrl}{PathPrefix}/{Slug}/index.html
```

## Workflow

1. Resolve the requested publication target:
   - Use an explicit request for a hosted URL as publication intent. For requests to view the map locally, use `mindmap-builder`.
   - Normalize `PathPrefix` to start with `/` and have no trailing `/`.
   - Normalize `PublicBaseUrl` to have no trailing `/`.
   - Validate `Slug` is one folder name made of letters, digits, hyphens, underscores, or dots, excluding `.` and `..`.
2. Verify source:
   - `SourceHtml` exists.
   - For legacy HTML referencing `markmap-assets/`, that sibling folder exists.
   - HTML does not contain `cdn.jsdelivr.net`.
3. Check `{StaticRoot}/{Slug}` before publishing. If `index.html` or the referenced legacy destination assets already exist, reuse explicit authorization to update this URL. Otherwise, ask whether to replace it or use a new slug, and show the destination URL.
4. Publish:
   - Use `scripts/publish_mindmap.ps1`.
   - Copy HTML as `index.html`.
   - Copy `markmap-assets/` only if the HTML references it.
   - Do not modify unrelated files.
5. Verify:
   - Destination `index.html` exists.
   - Any assets referenced by legacy HTML exist; single-file HTML needs none.
   - Returned URL includes the required `PathPrefix`.

## Script

Use:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\publish_mindmap.ps1 `
  -SourceHtml .\output.html `
  -StaticRoot D:\nginx\html\mindmaps `
  -PublicBaseUrl https://example.com `
  -PathPrefix /mindmaps `
  -Slug zero-trust-ai-agents
```

The script returns JSON containing:

```json
{
  "published_dir": "...",
  "index_file": "...",
  "url": "https://example.com/mindmaps/zero-trust-ai-agents/index.html"
}
```

## Deployment Notes

Read `references/nginx-static-publish.md` when the user needs help matching `StaticRoot`, `PublicBaseUrl`, and `PathPrefix` to an Nginx `location` or `alias` config.

This skill does not configure Nginx automatically. It publishes files to a configured static directory and computes the URL from user-provided deployment settings.
